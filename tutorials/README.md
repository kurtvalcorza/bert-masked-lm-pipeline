## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) filled one synthetic cloze, embedded three synthetic sentences and reported a `not-measurable` verdict because the repository shipped no metric and the sample had no labels. This notebook keeps both inference contracts as Section 5 (on an unseen abstract's cloze and two test abstracts instead of the synthetic sample) and adds the adaptation contract around it: a real corpus of paper abstracts, the model's own masked-language-model objective as the metric (seeded masks, perplexity, top-k accuracy) in the carried `metrics.py` with an add-one unigram floor as the reference point, a bounded continuation of that objective on the last encoder layers, before/after clozes and embedding cosines, and an artifact that reloads. The per-input `evaluation_report` still returns `not-measurable`; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `BERTMaskedLMPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib` or the model directly.
- **Data (DAT1–DAT9, ST6):** the default sample is three pinned objects — `train.jsonl` / `dev.jsonl` / `test.jsonl` of SciTLDR-A (3,155,015 / 1,124,865 / 1,204,107 bytes; SHA-256 `b222771d…` / `3191fa98…` / `fb42dd6c…`) from `raw.githubusercontent.com` at the pinned `allenai/scitldr` commit — each refused on any mismatch before it is parsed, reduced to the abstract text, filtered to 200..2,000 characters and de-duplicated, and drawn by a seeded shuffle into 300 / 50 / 100 records from the release's own paper-disjoint members (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the Apache-2.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.fill_mask` + `pipe.embed` with sanity checks and the frozen candidates for three unseen clozes (inference contracts) → `pipe.unigram_baseline` + `pipe.evaluate` on the frozen model (floor and baseline) → `pipe.adapt` (bounded continued pre-training) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.fill_mask` and `pipe.embed` after adaptation + `evaluation_report` (inference) → `pipe.save_artifact` → `BERTMaskedLMPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the fill-mask `score` is a softmax ranking signal, not a calibrated probability, and embeddings are representations; masked perplexity, bits per masked token and top-k accuracy are the model's own objective at seeded positions of held-out text (a record's `[CLS]`/`[SEP]` never masked, 100 % `[MASK]` replacement, tokenisation- and masking-dependent), not embedding quality or a human judgement; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the unigram floor and the frozen model are scored on the same 100 test abstracts at the same masked positions as the adapted model, `n_masked` is asserted equal across them, and every metric is labelled as one seeded masking of one seeded split of one corpus with no dispersion estimate; the notebook states that the adapter changes the shared encoder layers, prints each embedding's cosine to its frozen self, and presents clozes before and after as observations, not evidence.
- **Split integrity (SPL1–SPL8):** the split is seeded and text-disjoint (the release's own train/dev/test partition); validation selects the epoch and the test split is used for nothing but the final evaluation and the reload-parity check; the notebook states that documents from one collection or author must be split by that grouping.
- **Ceilings (VAL6):** `MAX_TEXT_CHARS` (4,000), `MAX_TEXT_TOKENS` (512, rejected not truncated — also for corpus records), `MAX_BATCH` (64), `MAX_TOP_K` (100), the record bounds (8..20,000) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one two-mask refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user documents flow through the same validation, seeded text-disjoint split, floor, frozen scoring, fine-tuning, evaluation, cloze and embedding checks, export and reload cells. The expected schema and the privacy guidance — an internal document collection is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/bert_masked_lm_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
